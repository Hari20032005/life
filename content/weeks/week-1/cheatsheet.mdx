## Week 1 cheat sheet

### HTTP status codes for the booking API
| Code | When |
|------|------|
| 200 | OK (GET/PUT/PATCH) |
| 201 | Created (POST) |
| 204 | Deleted, no body |
| 400 | Invalid input (Zod field errors) |
| 404 | Unknown resource or path |
| 409 | Conflict: overlapping booking, duplicate email |
| 500 | Unexpected error (no stack trace in body) |

### Express skeleton
```ts
app.use(express.json());
app.use("/services", servicesRouter);
app.use((req, res) => res.status(404).json({ error: { code: "NOT_FOUND", message: "Route not found" } }));
app.use((err, req, res, next) => {
  if (err instanceof SyntaxError) return res.status(400).json({ error: { code: "BAD_JSON", message: "Invalid JSON" } });
  if (err instanceof ConflictError) return res.status(409).json({ error: { code: "CONFLICT", message: err.message } });
  logger.error(err);
  res.status(500).json({ error: { code: "INTERNAL", message: "Something went wrong" } });
});
```

### Layering
routes (HTTP + Zod) → services (rules, transactions) → data access (Drizzle/SQL) → Postgres. Routes never contain SQL.
